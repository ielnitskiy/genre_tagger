# Чистка жанров: состояние и что дальше

Рабочий документ по приведению жанров медиатеки в порядок. Механика команд — в
`README.md`, здесь только состояние.

Обновлено: 2026-07-30.

## Откуда началось

Скан библиотеки (2225 исполнителей) дал **508 уникальных жанров**, больше
половины — мусор по 1-5 треков: гео-теги, служебные метки Last.fm, имена
артистов, настроения.

## Чем это лечилось и почему переделано

Первый подход был итеративным: сгенерировать список кандидатов, отредактировать,
применить через `--ban-genre-file`, повторить. Он не сходился.

Причина: бан отсекал теги **до** среза по топ-3, поэтому забаненный тег
освобождал слот, и в него поднимался следующий тег из хвоста ответа Last.fm —
тот, что раньше в ID3 не попадал вообще. Измерено на реальных данных: бан 177
тегов дал 390 жанров вместо ожидаемых 508−177=331. Вторая итерация бана довела
бан-лист до 422 записей, а число жанров выросло до 413.

Конвейер переписан на линейный (`топ-3 → бан → алиасы`, слот не
переиспользуется), а весь CLI управления списками заменён двумя текстовыми
файлами. Подробности — в `README.md`.

## Текущее состояние

Расчёт на реальной БД с подготовленными списками (177 забаненных, 65 групп
алиасов):

| | Жанров | Без жанра |
|---|---|---|
| было | 508 | 384 |
| стало | **178** | 414 |

Распределение: 3 жанра у 880 артистов, 2 — у 677, 1 — у 254.

## Что осталось сделать

1. **Обновить сервер:**
   ```bash
   cd ~/projects/media-server/genre_tagger
   git pull
   docker compose build --no-cache
   ```
2. **Положить подготовленные списки** в `./data/banlist.txt` и
   `./data/aliases.txt`. Если этого не сделать, первый `--once` сконвертирует
   старые `genre_banlist.json` (422 записи, с настоящими жанрами внутри) — этот
   файл лучше не брать за основу.
3. **Прогнать** `docker compose run --rm genre-tagger --once`. Пересчёт идёт
   локально из `raw_response`, Last.fm не дёргается.
4. **Проверить** `docker compose run --rm genre-tagger --report`.
5. **Убрать из .env** `MIN_TAG_COUNT`, `MAX_GENRES`, `BAN_AFTER_TOP_N` — этих
   параметров больше нет, они просто игнорируются.

Дальше — по мере роста библиотеки: `--report`, дописать пару строк в файлы,
`--once`.

## Полезное, чтобы не выяснять заново

- **`count` в ответе Last.fm — не число людей и не число треков.** Это вес
  *относительно топ-тега конкретного артиста* (у топ-тега всегда 100). Поэтому
  складывать веса разных написаний бессмысленно — берётся максимум.
- **Жанр резолвится по имени папки исполнителя**, а не из тегов файлов, и один
  на всю папку. Расхождение с каноническим именем на Last.fm даёт `genre=None`.
- **`--reset-artist` не пересканирует сам** — только сбрасывает кэш и ставит
  флаг. Для «сделать сейчас и только его» есть `--tag-artist`.
- **Осиротевшие записи кэша не удаляются автоматически** — только `WARNING` на
  каждом проходе.
- **`--wipe-all-genres`** — аварийный полный сброс. Без `--yes` только
  показывает масштаб.
- **Бэкап `./data` под git.** `banlist.txt` и `aliases.txt` — обычный текст,
  `git diff` покажет ровно то, что изменилось.
