# Чистка жанров: текущая стадия и что дальше

Рабочий документ по разовой кампании приведения жанров медиатеки в порядок.
Механика самих команд — в `README.md`, здесь только состояние и порядок шагов.

Зафиксировано: 2026-07-30. Последний коммит на момент записи — `456907c`.

## Откуда началось

Скан всей библиотеки (~2600 папок исполнителей) дал **~508 уникальных жанров**,
из которых больше половины — мусор по 1-5 треков. Цель: сократить до
осмысленного набора, а не чистить это заново каждые полгода.

## Что уже сделано

### Инфраструктура (в коде, запушено)

| Задача | Инструменты |

| Аудит | `scripts/dump_tags.py`: метрика **по трекам** (не по весу Last.fm), `--max-tracks`, `--no-clusters` / `--only-clusters` |
| Бан мусора | `--ban-genre` (несколько за раз), `--ban-genre-file`, `--ban-below`, `--suggest-bans-file`, `--list-banned-genres` |
| Алиасы | групповой формат файла, `--add-alias`, `--add-alias-file`, `--remove-alias`, `--list-aliases`, `--suggest-aliases-file` |
| Точечная работа | `--tag-artist`, `--limit` |

Ключевые исправления по ходу:

- **`eae825b`** — артист с папкой альбома без единого `.mp3` (незавершённая
  закачка spotDL) больше не дёргает Last.fm и не кэшируется. Это был корень
  расхождения «треков меньше, чем артистов» и источник осиротевших записей.
- **`21a6f69`** — формат словаря алиасов стал групповым (главный тег → список
  вариантов); закрыты: обход бан-листа через алиас, молчаливая перезапись
  записи, случайное создание цепочек, отсутствие `--remove-alias`.
- **`38d5ee5`** — бан-часть отвязана от веса Last.fm: только локальный счётчик
  треков, сортировка по убыванию.
- **`290fb4e`** — забаненные теги исключены из кандидатов на алиасы (их
  `--add-alias` всё равно не примет).
- **`456907c`** — файловый пачечный процесс для алиасов, симметричный бану.

## Что делать дальше

### Шаг 0. Обновить сервер

```bash
cd ~/projects/media-server/genre_tagger
git pull
docker compose build --no-cache   # нужен: менялись src/
```

Пересборка обязательна для команд, идущих через `docker compose run`.
`scripts/dump_tags.py` запускается хостовым python и в образ не входит.

Отсюда же разница в путях ниже: `dump_tags.py` получает файлы как
`./data/...` (хостовый путь), а `docker compose run` — как `/data/...`
(`WORKDIR=/app` внутри контейнера, том смонтирован как `./data:/data`).
Передадите контейнеру `./data/...` — получите `No such file`.

### Шаг 1. Бан-проход по мусору

```bash
# полный список всех незабаненных тегов (без --max-tracks = без порога)
python3 scripts/dump_tags.py --db-path ./data/genres.db --no-clusters \
  --suggest-bans-file ./data/ban_candidates.txt

nano ./data/ban_candidates.txt   # удалить строки с жанрами, которые ОСТАВЛЯЕМ

docker compose run --rm genre-tagger --ban-genre-file /data/ban_candidates.txt
docker compose run --rm genre-tagger --once
```

Отдельно добить служебные теги Last.fm: они стоят на большом числе треков и под
порог `--max-tracks 10` не попадут, а жанрами не являются:

```bash
docker compose run --rm genre-tagger --ban-genre \
  "yandex music" "yander music" "under 2000 listeners" "under 100 listeners" \
  "upcoming album 2022" "upcoming album 2023" "upcoming album 2024" "upcoming album 2025"
```

### Шаг 2. Алиасы по тому, что осталось

Только после шага 1: алиасы имеют смысл лишь для жанров, которые оставляем.
Порядок поддержан механикой — `--add-alias` отказывается работать с забаненным
жанром, забаненные теги не попадают в заготовку.

```bash
python3 scripts/dump_tags.py --db-path ./data/genres.db --only-clusters \
  --suggest-aliases-file ./data/alias_draft.txt

nano ./data/alias_draft.txt

docker compose run --rm genre-tagger --add-alias-file /data/alias_draft.txt
docker compose run --rm genre-tagger --once
```

Заготовка из двух секций, и работать надо с обеими:

1. **Предположения `difflib`** — готовые строки `главный тег <- варианты`.
   Проверять обязательно: группировка по **написанию**, не по смыслу, поэтому
   попадается мусор вида `art rock <- hard rock, rock, pop rock`. Главным тегом
   взят первый по алфавиту — часто не тот, что нужен.
2. **Остальные теги, закомментированные, по алфавиту** — здесь ловятся синонимы,
   которые `difflib` не найдёт в принципе, потому что у них нет общего написания
   (`dnb` ↔ `drum and bass`). Раскомментировать и оформить вручную. Алфавитный
   порядок для этого и нужен: родственные написания стоят рядом.

`--add-alias-file` — всё или ничего: любая плохая строка отменяет весь файл со
списком проблем и номерами строк.

## Что стоит обсудить/решить отдельно

- **Служебные теги Last.fm в встроенный блоклист.** `yandex music`,
  `under N listeners`, `upcoming album YYYY` — это не вкусовщина конкретной
  библиотеки, а мусор для всех. Возможно, им место в `TAG_BLOCKLIST`
  (`src/lastfm.py`), а не в пользовательском бан-листе.
- **Подкрутить `MIN_TAG_COUNT` / `MAX_GENRES`.** Сейчас 10 и 3. Если после
  чистки жанров всё ещё много — поднять `MIN_TAG_COUNT`; смена автоматически
  пересчитает всю библиотеку офлайн, без запросов к Last.fm.
- **Алиасы могут «проявить» скрытые жанры.** Подстановка идёт до отсечения по
  `MIN_TAG_COUNT`, и веса вариантов складываются: два варианта по 6 при пороге
  10 по отдельности отсеиваются, а после алиаса дают 12 и проходят. Это обычно
  желаемое поведение, но объясняет, откуда после алиас-прохода может появиться
  жанр, которого раньше в ID3 не было.
- **Бэкап `./data` под git.** Бан-лист и словарь алиасов — отсортированный JSON,
  так что `git diff` покажет ровно то, что изменилось между прогонами. Полезно,
  когда файлы разрастутся.

## Полезное, чтобы не выяснять заново

- **`count` в ответе Last.fm — не число людей и не число треков.** Это вес
  *относительно топ-тега конкретного артиста* (у топ-тега всегда 100). Поэтому
  «891» в старом выводе `dump_tags.py` никак не соотносился с 8 треками в
  плеере. Для решений о бане используется **только** локальный счётчик треков.
- **Жанр резолвится по имени папки исполнителя**, а не из тегов файлов, и один
  на всю папку. Расхождение имени папки с каноническим на Last.fm даёт
  `genre=None` (`autocorrect=1` помогает лишь частично).
- **`--reset-artist` не пересканирует сам** — только сбрасывает кэш и ставит
  флаг; работа происходит на следующем `--once`. Для «сделать сейчас и только
  его» есть `--tag-artist`.
- **Осиротевшие записи кэша не удаляются автоматически** — только `WARNING` на
  каждом проходе (см. ограничение 6 в `README.md`). Чистить руками, как в этот
  раз.
- **`--wipe-all-genres`** — аварийный полный сброс (снять genre со всех mp3 +
  обнулить кэш). Без `--yes` только показывает масштаб.
