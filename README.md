# genre_tagger

Отдельный сервис, который берёт жанр исполнителя с Last.fm (`artist.getTopTags`)
и проставляет его в ID3-тег (TCON) всех mp3-файлов этого исполнителя в `/music`.
Не связан с ботом по сети — независимо периодически сканирует файловую систему.
Полное описание архитектуры и алгоритма — в `PLAN.md`.

## Управление сервисом (шпаргалка)

1. **Настройка (один раз):**
   ```
   cp .env.example .env   # заполнить LASTFM_API_KEY
   docker compose build
   ```
2. **Поставить на cron (один раз)** — контейнер не демон, `restart: "no"`, запускается только так. Пример на 03:00 ночи, с `--force-scan` на всякий случай (см. ограничение 5):
   ```
   crontab -e
   0 3 * * * cd /home/biobojlk/projects/genre_tagger && /usr/bin/docker compose run --rm genre-tagger --once --force-scan >> /var/log/genre-tagger.log 2>&1
   ```
3. **Разовый ручной запуск** (то же, что делает cron):
   ```
   docker compose run --rm genre-tagger --once
   ```
3a. **Пробный запуск на первых N исполнителях** (проверить, что всё работает нормально, перед тем как отпускать на всю библиотеку) — обрабатывает только первые N папок по алфавиту, остальные не трогает:
   ```
   docker compose run --rm genre-tagger --once --limit 50
   ```
   Повторный запуск с тем же `--limit` не натегирует что-то новое, если эти N артистов уже обработаны (сработает обычный mtime-gate) — это не постраничный обход библиотеки, а именно "первые N" каждый раз.
4. **Пересканировать всё, игнорируя кэш mtime** (не трогая Last.fm и уже проставленные теги):
   ```
   docker compose run --rm genre-tagger --once --force-scan
   ```
5. **Сбросить одного артиста** (форсирует повторный запрос к Last.fm и перезапись его тегов на следующем проходе):
   ```
   docker compose run --rm genre-tagger --reset-artist "Имя Исполнителя"
   ```
5a. **Промаппить одного артиста прямо сейчас** — то же самое, что reset + `--once`, но без скана остальной библиотеки: сразу сбрасывает кэш и обрабатывает только этого исполнителя (запрос к Last.fm + перезапись ID3). Имя должно точно совпадать с именем папки в `MUSIC_DIR`:
   ```
   docker compose run --rm genre-tagger --tag-artist "Имя Исполнителя"
   ```
6. **Посмотреть логи cron-запусков:**
   ```
   tail -f /var/log/genre-tagger.log
   ```
7. **Обновить конфиг** (`MIN_TAG_COUNT`/`MAX_GENRES` в `.env`) — ничего руками пересчитывать не нужно, сервис сам обнаружит смену при следующем запуске и пересчитает жанры из уже сохранённого `raw_response`.
8. **БД** — `./data/genres.db`, создаётся автоматически при первом запуске, ничего вручную инициализировать не надо. Удаление файла = полный сброс кэша всех артистов.
9. **Добавить синоним жанра** (см. "Синонимы жанров" ниже) — правит только файл словаря, реальный пересчёт произойдёт на следующем обычном запуске:
   ```
   docker compose run --rm genre-tagger --add-alias hiphop "hip hop"
   ```
10. **Полностью стереть все жанры** (ОПАСНО, необратимо без бэкапа файлов) — снимает genre-тег со всех mp3 в `MUSIC_DIR` и полностью сбрасывает кэш, все артисты станут "новыми". Без `--yes` ничего не меняет, только показывает, сколько файлов затронет:
    ```
    docker compose run --rm genre-tagger --wipe-all-genres          # dry-run, отчёт в лог
    docker compose run --rm genre-tagger --wipe-all-genres --yes    # реальное удаление
    ```

`SCAN_INTERVAL_SECONDS` в `.env` не используется в этой схеме (это параметр run-loop-режима, которым сервис не пользуется — интервал задаётся расписанием cron).

## Синонимы жанров (ska-punk vs ska punk и т.п.)

`lastfm.py` автоматически схлопывает варианты одного тега, различающиеся
только регистром/дефисом/пробелом/подчёркиванием (`Ska-Punk` = `ska punk` =
`SKA_PUNK`). Но настоящие синонимы без общего написания (`hiphop` без пробела,
`dnb` вместо `drum and bass`) так не поймать — для них нужен ручной словарь
замен, собранный по факту того, что реально встречается в вашей библиотеке:

```
python3 scripts/dump_tags.py --db-path ./data/genres.db
```

Скрипт не обращается к сети — берёт уже накопленный в кэше `raw_response`
каждого артиста, агрегирует по всей библиотеке и печатает:
1. отсортированный список канонических тегов с суммарным весом;
2. кандидатов на объединение — теги, похожие по написанию (`difflib`), которые
   легко пропустить при простом просмотре списка (`hip hop` / `hiphop`).

`--cutoff` (0..1, по умолчанию 0.8) регулирует строгость похожести,
`--min-count` — отсекает совсем редкие теги из вывода.

Дальше словарь синонимов добавляется через сам сервис, без ручного
редактирования JSON:

```
docker compose run --rm genre-tagger --add-alias hiphop "hip hop"
docker compose run --rm genre-tagger --list-aliases
```

Словарь лежит в `GENRE_ALIASES_FILE` (по умолчанию `/data/genre_aliases.json`,
внутри уже смонтированного `./data`, переживает пересоздание контейнера).
`--add-alias FROM TO` только правит файл и не сканирует библиотеку. Реальный
эффект — на следующем обычном запуске (`--once` из cron): изменение словаря
меняет `config_hash`, и сервис, как и при смене `MIN_TAG_COUNT`/`MAX_GENRES`,
локально пересчитывает жанры **всех** уже обработанных артистов из
сохранённого `raw_response` (без единого нового запроса к Last.fm) и форсирует
перезапись ID3 у всех, чей жанр реально изменился. Т.е. один раз добавленный
алиас автоматически лечит уже прометённую библиотеку целиком, а не только
новых артистов.

```
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

Тесты не обращаются к реальному Last.fm (HTTP замокан через `responses`) и не
требуют настоящих mp3-файлов (синтетические MPEG-фреймы из `tests/conftest.py`).

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MUSIC_DIR` | `/music` | Корень медиатеки (`{artist}/{album}/{title}.mp3`) |
| `DB_PATH` | `/data/genres.db` | SQLite-кэш "исполнитель уже обработан" |
| `LASTFM_API_KEY` | — (обязательна) | Ключ Last.fm, read-only метод, `LASTFM_SECRET` не нужен |
| `SCAN_INTERVAL_SECONDS` | `86400` | Интервал между проходами в режиме демона (не используется при запуске через cron + `--once`) |
| `MIN_TAG_COUNT` | `10` | Минимальный `count` тега на Last.fm, чтобы не считаться шумом |
| `MAX_GENRES` | `3` | Сколько топ-тегов брать как жанры |
| `GENRE_TTL_DAYS` | `180` | Через сколько дней после `processed_at` заново дёргать Last.fm для уже обработанного артиста (жанры на Last.fm могли поменяться) |
| `SKIP_DIRS` | `download-errors` | Через запятую — top-level папки в `MUSIC_DIR`, которые не считаются исполнителями |
| `LOG_LEVEL` | `INFO` | Уровень логирования (`DEBUG`/`INFO`/`WARNING`/...); невалидное значение откатывается на `INFO` с предупреждением в stderr |

Смена `MIN_TAG_COUNT`/`MAX_GENRES` между запусками автоматически пересчитывает
жанры уже обработанных исполнителей из сохранённого ответа Last.fm (без новых
сетевых запросов) и форсирует перезапись их ID3-тегов на следующем проходе.

## Известные ограничения

1. **Шум/отсутствие тегов на Last.fm** — часть исполнителей получит `genre=NULL`
   и останется без тега вплоть до `GENRE_TTL_DAYS` (по умолчанию 180 дней), когда
   сервис сам перепроверит жанр у Last.fm. Форсировать раньше — `--reset-artist`.
2. **Расхождение имени папки и канонического имени на Last.fm** —
   `autocorrect=1` помогает частично; жёсткие расхождения (транслитерация,
   "The"-префиксы) дают `genre=None`.
3. **Один жанр на всю папку исполнителя** — сборники/"Various Artists" получат
   один и тот же жанр на все файлы (не обрабатывается в MVP).
4. **`has_genre`-guard на самом первом проходе нового исполнителя** — если у
   файла уже стоял genre до того, как сервис впервые дошёл до исполнителя
   (вручную или из другого источника), Last.fm не перезапишет его. На практике
   почти не встречается, так как spotDL никогда не пишет genre сам.
5. **Надёжность mtime-gate** — алгоритм полагается на то, что изменение
   содержимого папки альбома обновляет её mtime (стандартно для POSIX ФС).
   Если `/mnt/music` смонтирован по сети (NFS/SMB) с нестандартным кэшированием
   атрибутов, это стоит проверить эмпирически после деплоя.
6. **Осиротевшие записи в кэше** — если папку артиста удалить с диска, запись в
   `artist_genre` не удаляется автоматически, только логируется как `WARNING`
   на каждом проходе. Чистить вручную — `--reset-artist`.
