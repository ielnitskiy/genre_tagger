# genre_tagger

Сервис берёт жанр исполнителя с Last.fm (`artist.getTopTags`) и проставляет его
в ID3-тег (TCON) всех mp3 этого исполнителя в `/music`. С ботом по сети не
связан — независимо периодически сканирует файловую систему. Описание
архитектуры и алгоритма обхода — в `PLAN.md`.

## Как выбирается жанр

```
теги Last.fm → выбросить служебные → топ-3 по весу → banlist.txt → aliases.txt → 0..3 жанра
```

Слева направо, без исключений и обратных связей. Каждый шаг только выбрасывает
или переименовывает уже выбранное:

1. **Служебные теги** (`seen live`, `favorite`, годы) отсекаются встроенным
   блоклистом — они не жанры ни для какой библиотеки.
2. **Топ-3 по весу.** Ровно три, больше не бывает. При равном весе — по алфавиту,
   чтобы результат не зависел от порядка ответа API.
3. **Бан-лист.** Тег из `banlist.txt` выбрасывается. Освободившийся слот **не**
   заполняется — на его место ничего не поднимается.
4. **Алиасы.** Оставшиеся теги переименовываются по `aliases.txt`. Если два тега
   свелись к одному, останется один.

Сколько тегов пережило конвейер, столько и уйдёт в ID3 — три, два, один или ни
одного. У исполнителя без жанра тег `genre` просто не выставляется.

Порога веса нет намеренно: на реальной библиотеке из 2225 исполнителей он менял
результат со 178 жанров до 149, то есть не решал ничего, а объяснять его
приходилось каждый раз.

## Два файла, которыми вы всем управляете

Оба лежат рядом с базой в `./data` и правятся обычным редактором. CLI-команд для
их изменения нет: файл нагляднее, чем восемь команд через docker.

**`data/banlist.txt`** — жанры, которые никогда не попадут в ID3. По одному на
строку:

```
russian          # гео-теги — не жанры
yandex music     # служебная метка Last.fm
audiobook
```

**`data/aliases.txt`** — сведение написаний и поджанров к одному имени:

```
hip hop <- hiphop, hip-hop
metalcore <- metacore, progressive metalcore, melodic metalcore
lo fi <- lofi, lofi beats
```

В обоих файлах `#` и всё после него — комментарий, пустые строки игнорируются,
регистр и дефисы не важны (`Hip-Hop` и `hip hop` — одно и то же).

Кривая строка не отменяет весь файл: она пропускается с `WARNING` в логе, а
остальные применяются. Проверяются и предупреждаются: алиас на забаненный жанр
(бан сильнее), цепочки `a → b → c` (разворачиваются в `a → c`), циклы, один
вариант в двух группах.

После правки — обычный `--once`. Сервис заметит изменение файлов и пересчитает
жанры **всей** библиотеки локально из сохранённых ответов Last.fm, без единого
сетевого запроса, переписав ID3 там, где результат изменился.

## Команды

```bash
docker compose run --rm genre-tagger --once      # проход: новые артисты + применение списков
docker compose run --rm genre-tagger --report    # что сейчас в библиотеке
```

`--report` печатает жанры по числу треков (редкие внизу — кандидаты в
`banlist.txt`) и группы похожих по написанию (готовые строки для `aliases.txt`).
Ничего не меняет и в сеть не ходит.

Рабочий цикл: `--report` → поправить файлы → `--once` → `--report`.

### Остальное

```bash
docker compose run --rm genre-tagger --once --limit 50      # пробный прогон на первых 50 папках
docker compose run --rm genre-tagger --once --force-scan    # игнорировать mtime-gate
docker compose run --rm genre-tagger --reset-artist "Имя"   # заново спросить Last.fm об артисте
docker compose run --rm genre-tagger --tag-artist "Имя"     # то же, но прямо сейчас и только он
docker compose run --rm genre-tagger --wipe-all-genres      # dry-run: сколько файлов затронет
docker compose run --rm genre-tagger --wipe-all-genres --yes  # ОПАСНО: снять все жанры и сбросить кэш
```

Путь к файлу внутри контейнера — всегда `/data/...`: `WORKDIR=/app`, а `./data`
смонтирована как `/data`. Для `banlist.txt`/`aliases.txt` это неважно (сервис
находит их сам), но пригодится, если понадобится передать файл флагом.

## Установка

```bash
cp .env.example .env    # заполнить LASTFM_API_KEY
docker compose build
```

Контейнер не демон (`restart: "no"`), поэтому регулярность — через cron:

```
crontab -e
0 3 * * * cd /home/biobojlk/projects/media-server/genre_tagger && /usr/bin/docker compose run --rm genre-tagger --once --force-scan >> /var/log/genre-tagger.log 2>&1
```

`SCAN_INTERVAL_SECONDS` при такой схеме не используется — это параметр
run-loop-режима, интервал задаёт расписание cron.

БД `./data/genres.db` создаётся сама при первом запуске. Удаление файла — полный
сброс кэша всех артистов (Last.fm будет опрошен заново).

## Переход со старой версии

Если в `./data` лежат `genre_banlist.json` и `genre_aliases.json` от прежней
версии, первый же `--once` сконвертирует их в `banlist.txt` и `aliases.txt`.
Исходные JSON остаются на диске нетронутыми. Повторно конвертация не сработает:
как только `.txt` существует, источник правды — он.

Заодно исчезли `--ban-genre`, `--ban-genre-file`, `--list-banned-genres`,
`--add-alias`, `--add-alias-file`, `--remove-alias`, `--list-aliases` и
`scripts/dump_tags.py` со всеми его флагами. Всё это заменили два текстовых
файла и `--report`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LASTFM_API_KEY` | — (обязательна) | Ключ Last.fm, read-only метод, `LASTFM_SECRET` не нужен |
| `MUSIC_DIR` | `/music` | Корень медиатеки (`{artist}/{album}/{title}.mp3`) |
| `DB_PATH` | `/data/genres.db` | SQLite-кэш "исполнитель уже обработан" |
| `BANLIST_FILE` | `/data/banlist.txt` | Список запрещённых жанров |
| `ALIASES_FILE` | `/data/aliases.txt` | Словарь синонимов |
| `GENRE_TTL_DAYS` | `180` | Через сколько дней перепроверить жанр у Last.fm |
| `SCAN_INTERVAL_SECONDS` | `86400` | Пауза между проходами в run-loop-режиме (без `--once`) |
| `SKIP_DIRS` | `download-errors` | Папки верхнего уровня, которые не считаются исполнителями |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

## Известные ограничения

1. **Шум/отсутствие тегов на Last.fm** — часть исполнителей получит `genre=NULL`
   и останется без тега вплоть до `GENRE_TTL_DAYS` (по умолчанию 180 дней), когда
   сервис сам перепроверит жанр. Форсировать раньше — `--reset-artist`.
2. **Расхождение имени папки и канонического имени на Last.fm** —
   `autocorrect=1` помогает частично; жёсткие расхождения (транслитерация,
   "The"-префиксы) дают `genre=None`.
3. **Один жанр на всю папку исполнителя** — сборники/"Various Artists" получат
   один и тот же жанр на все файлы.
4. **`has_genre`-guard на самом первом проходе нового исполнителя** — если у
   файла уже стоял genre до того, как сервис впервые дошёл до исполнителя,
   Last.fm не перезапишет его. На практике почти не встречается: spotDL никогда
   не пишет genre сам.
5. **Надёжность mtime-gate** — алгоритм полагается на то, что изменение
   содержимого папки альбома обновляет её mtime (стандартно для POSIX ФС).
   Если `/mnt/music` смонтирован по сети (NFS/SMB) с нестандартным кэшированием
   атрибутов, это стоит проверить эмпирически.
6. **Осиротевшие записи в кэше** — если папку артиста удалить с диска, запись в
   `artist_genre` не удаляется автоматически, только логируется как `WARNING`
   на каждом проходе.
